Project brief · sohohold/nuance-mapper

Nuance Mapper

入力した言葉の類語・言い換えを LLM で生成し、ユーザーが選んだ 2 つの評価軸の上に配置して、意味の近さだけでは見えない「ニュアンスの違い」を地図として見せる Web アプリです。

フロント　Next.js 16 / React 19。結果は SSE で 1 語ずつ届き、React Flow のマップに順次描画されます。

API　無料枠の LLM 4 社を時間差で並列に呼び、最初に品質基準を満たした結果を採用します。

運用　Docker イメージをさくらの AppRun へ。PR ごとのプレビュー環境と Terraform による本番デプロイを GitHub Actions で自動化しています。

A · System

全体構成

1 つの Next.js アプリが画面と API を兼ね、コンテナとしてさくらのクラウド AppRun 上で動きます。外部依存はキャッシュ用の Redis と、OpenAI 互換 API を持つ LLM プロバイダだけです。

B · Request lifecycle

生成 API の流れ

src/app/api/generate/route.ts が 1 回の POST を次の順に処理します。右列は、その段階でリクエストが途中で終わる条件です。

  1. レート制限

    クライアント IP ごとに 1 分あたり 10 回までの固定ウィンドウ。カウンタはプロセス内メモリ。

    429超過時は Retry-After 付きで拒否

  2. 入力検証

    ブラウザと同じ validateWord / validateAxisLabel を使用。前後の空白を除いたコードポイント数で 24 文字まで。

    400型違い・空・文字数超過

  3. キャッシュ照会

    キーは「語｜X 軸｜Y 軸」を NFKC 正規化して連結。大文字小文字は区別します。

    ヒットLLM を呼ばずに即 SSE 配信

  4. LLM を時間差で並列呼び出し

    キーが設定されたプロバイダを優先順に 7 秒間隔で起動し、最初に合格した結果を採用。詳細は C。

    モックキーが 1 つも無ければ固定データを返す

  5. パースとサニタイズ

    <think> ブロックやコードフェンスを除去し、JSON を段階的に修復。件数 40・語 60 字・解説 120 字の上限、座標を ±10 に丸め、重複語を除去。

  6. 品質判定

    12 語以上、かつ 3 象限以上に分布していれば合格。

    不合格次のモデルへ。全滅なら最良結果を縮退表示

  7. キャッシュ保存

    合格した結果だけを 30 日保存。縮退結果は保存しません。

  8. SSE で配信

    最初にメタ情報（キャッシュ由来か、縮退か）を送り、続いて 1 語ずつ 40 ms 間隔で送信し、[DONE] で終了。

C · Hedged requests

LLM の時間差並列（ヘッジ）

無料枠の LLM は応答時間とレート制限のばらつきが大きいため、1 社ずつ順番に待つのではなく、時間差で候補を追加しながら競争させます。

MODEL RESOLUTION

モデル名の変更に追従

各社の /models を 2 秒以内で問い合わせ、優先リストの中で提供中の先頭モデルを選びます。成功時は 1 時間、失敗時は 5 分キャッシュし、失敗時は前回成功したモデルを使います。

SEQUENTIAL FALLBACK

プロバイダ内の直列切り替え

OpenRouter だけは同じプロバイダ内で次のモデルへ直列に切り替えます。モデルごとにタイムアウトを取り直すので、後続のモデルも待ち時間を満額使えます。

TOOL OUTPUT

JSON 形式の強制

OpenRouter 経由のモデルには strict な関数スキーマ submit_nuances を渡し、tool call の引数として結果を受け取ります。

D · Untrusted input and output

プロンプトインジェクションと不正な出力への備え

ユーザー入力はプロンプトに埋め込まれ、モデルの出力は画面とキャッシュに入ります。どちらも信頼せず、独立した 3 層で扱います。

LAYER 1 · 決定的

入力の無害化

改行・制御文字・双方向制御文字を空白に置換し、< > ` を全角や別記号へ置き換えます。24 文字の値では見出しを作ることも、</user_input> を偽装することもできません。

LAYER 2 · 確率的

システムプロンプト

入力ブロックはデータであり指示ではないこと、規則を開示しないこと、JSON 以外を返さないことを最優先の規則として明記します。確実な防御ではないため、単独では頼りません。

LAYER 3 · 決定的

出力の検証

sanitizeItems がスキーマ・文字数・座標を検査し、qualityIssue が件数と分布を判定します。指示を無視した応答はここで不合格になり、次のモデルへの切り替えとして扱われます。

パースは 4 段階です。応答全体を JSON として解釈 → 最外の配列だけを切り出して解釈 → 切り出した配列を jsonrepair で修復 → 全体を修復。修復を配列の切り出しより後に置いているのは、前置きの文章ごと修復すると文章が配列の要素に化けるためです。

E · Degradation

障害時・縮退時の挙動

依存先のどれかが使えなくても、可能な限り画面に何かを返す方針です。

状況応答挙動
Redis が障害・2 秒超過通常キャッシュミスとして扱い生成を続行。キャッシュの障害で API を停止させない
Redis が未設定通常プロセス内メモリ（最大 200 件）とローカルファイルに保存。サーバーレスではインスタンス間で共有されない
優先モデルが提供終了通常/models から次に提供中のモデルを解決
全モデルが品質基準未達縮退3 語以上の最良結果を返し、画面に「参考結果」と表示。キャッシュには保存しない
全プロバイダがレート制限（429）縮退保存済みの結果があれば返す（再生成を要求された場合も含む）。無ければ 429 と Retry-After 60 秒
API キーが 1 つも無いモック外部 API を呼ばず固定のモックデータを返す。キーなしでローカル開発を始められる
同一 IP からの過剰なリクエスト拒否1 分 10 回を超えた時点で 429

F · Client

フロントエンド

画面は 1 ページで、状態は page.tsx が保持します。マップはブラウザ専用のため動的 import で SSR から外しています。

STREAMING

SSE の逐次反映

fetch の ReadableStream を読み、1 語届くたびに配列へ追加します。メタ情報でキャッシュ由来・縮退を受け取り、「再生成」ボタンでキャッシュを飛ばした再要求を送れます。

MAP

React Flow による配置

座標 1 単位をデスクトップで 50 px、モバイルで 20 px に換算。同じ座標の語は 1 点にまとめ、ツールチップから個別に確認・コピーできます。象限の色はノード・ミニマップ・ツールチップで共通です。

LEGIBILITY

ズーム時の文字サイズ補正

拡大時はズーム率の逆数で文字を縮め、ラベル同士が重ならないようにします。縮小時は最小の文字（軸の目盛り）が 8 px を下回らないよう、逆に拡大して下限を保ちます。

その他：6 種の評価軸プリセットと軸ラベルの自由入力、日本語 / 英語の辞書切り替え（プリセットは ID で選択状態を保持）、モバイルでは 1 画面に収まるレイアウトとし、キャンバスだけがパンする構成。

I · Talking points

説明できる設計判断

面談で質問されやすい「なぜそうしたか」を、根拠のコードとあわせてまとめています。

なぜ順番に試すのではなく、時間差で並列に呼ぶのか

無料枠のモデルは遅延と 429 のばらつきが大きく、直列では最悪時の待ち時間が各社のタイムアウトの合計になります。時間差の並列なら速い候補が勝ち、負けた候補は中断するため、呼び出し回数の増加も限定的です。

route.ts · hedgedGenerate

縮退した結果をキャッシュしない理由

一時的に質の低い生成が出ただけで、同じ入力が 30 日間その結果に固定されるのを避けるためです。保存しなければ、次のリクエストで改めて生成を試せます。

route.ts · if (!degraded) cacheSet

プロンプトインジェクションをどう扱ったか

システムプロンプトの指示は確率的にしか守られない前提で、前後を決定的な処理で挟みました。仮に注入が成功しても、出力検証で不合格になり別モデルへの切り替えで終わります。

prompt.ts · model-output.ts

検証ルールをブラウザと API で共有する理由

同じ関数を両側で使うため、画面で入力できた値がサーバーで拒否されることがありません。文字数は UTF-16 の長さではなくコードポイント数で数え、絵文字でも表示中のカウンタと一致します。

validation.ts · countChars

PR プレビューを安全に公開する方法

認証が必須のフラグがあるのに資格情報が揃っていない間は 503 を返し、公開状態になりません。デプロイ後に認証が有効かを検証し、失敗したプレビューは削除します。本番のシークレットは PR のイメージに渡しません。

proxy.ts · preview-sakura.yml

イメージタグをコミット SHA にする理由

AppRun はイメージ参照の文字列が変わらないと新しいバージョンを作らないため、同じタグの上書きでは push が成功しても何もデプロイされません。一意なタグに加え、/api/health が返す revision で稼働中のビルドを確認できるようにしました。

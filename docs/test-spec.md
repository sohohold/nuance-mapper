# テスト仕様書

Nuance Mapper の振る舞いを定義する文書。実装より先にこの表を書き、表の各行に対応するテストを置く。仕様を変えるときはコードより先にこの表を変える。

## 実行

| コマンド | 対象 |
| --- | --- |
| `pnpm test` | ユニット・API・コンポーネント（Vitest） |
| `pnpm test:watch` | 同上、ウォッチモード |
| `pnpm test:e2e` | ブラウザ（Playwright） |
| `pnpm typecheck` | 型検査 |
| `pnpm lint` | 静的解析 |

`pnpm test` と `pnpm test:e2e` は CI で全 PR に対して実行される（`.github/workflows/ci.yml`）。

現在: **276 テスト**（Vitest 240 / Playwright 36）。

## テスト層

| レイヤ | 実行環境 | 置き場所 | 担当範囲 |
| --- | --- | --- | --- |
| `unit` | Vitest / node | `src/lib/*.test.ts` | 純関数。入出力のみで完結し、ネットワーク・時刻・環境に依存しない |
| `api` | Vitest / node | `src/app/api/**/*.test.ts` | ルートハンドラ。モデル・キャッシュ・モデル一覧取得はすべて差し替える |
| `component` | Vitest / jsdom | `src/**/*.test.tsx` | React コンポーネントの状態遷移と DOM 出力 |
| `e2e` | Playwright / Chromium | `e2e/*.spec.ts` | 実レイアウトの寸法・座標。本番ビルドに対して実行する |

判定基準の割り当て方:

- **寸法・座標・重なり・スクロール**は `e2e`。jsdom にはレイアウトが存在せず、数値が意味を持たない。
- **時間の境界**（何ミリ秒で出る／消える）は `component`。偽タイマーで正確に刻める。
- **失敗経路**（400 / 429 / 500 / フェイルオーバー）は `api`。ブラウザからは再現しにくく、実行も遅い。
- 上記に当てはまらない判定は `unit` に落とせないか先に検討する。

### 外部依存の扱い

LLM プロバイダは常にモックする。応答が非決定的で、API キーと課金を要し、CI では再現できないため。実プロバイダを叩くテストは追加しない。

キャッシュ（Redis / ローカル）とプロバイダの `/models` 照会も同様に差し替える。`e2e` では `/api/generate` を Playwright のルートハンドラで固定応答に置き換え、座標を制御する。

### テスト環境の補正

jsdom には存在しない機能を `vitest.setup.ts` で補う。理由は同ファイル内に記載。要点のみ:

- React Flow は ResizeObserver がサイズを報告するまでノードを `visibility: hidden` にする。jsdom はレイアウトを持たないため、寸法を返すシムを入れないとノードを取得できない。
- Tailwind のスタイルシートは読み込まれない。マーカーの `pointer-events` を戻すユーティリティだけ宣言し、user-event の pointer-events 判定を有効なまま保つ。
- 幾何に関する主張はここでは行わない。すべて Playwright 側で計測する。

## 仕様

テスト表が参照する共通の決めごと。

### 入力の制限

| 項目 | 値 |
| --- | --- |
| 単語の上限 | 24 文字 |
| X軸ラベルの上限 | 24 文字 |
| Y軸ラベルの上限 | 24 文字 |

- 上限は `GENERATION_CONFIG.input`（`src/lib/config.ts`）の 1 か所で定義する。
- 文字数は**コードポイント**で数える（`Array.from(value).length`）。`"👍"` は 1 文字。UTF-16 単位で数えると「24 文字」が絵文字 12 個を意味してしまい、画面のカウンタと一致しない。ZWJ で連結された絵文字（`"👨‍👩‍👧"`）は構成コードポイント数で数える。
- 前後の空白を除去した値を数える。末尾の空白で弾かれない。
- 空文字・空白のみ（半角・全角・改行・タブ）は不正とする。
- ブラウザと API ルートは `src/lib/validation.ts` の**同一の関数**を使う。UI が弾く入力は、UI を経由しない要求でも同じ理由で弾かれる。

### プロンプトインジェクション対策

3 層で構成する。決定的に保証できるのは 1 と 3、2 は緩和策である。

| 層 | 実装 | 性質 | 破られたとき |
| --- | --- | --- | --- |
| 1. 入力の構造無害化 | `sanitizePromptInput()`（`src/lib/prompt.ts`）。改行・制御文字・bidi 上書き・ゼロ幅文字を除去し、`<` `>` を全角化、`` ` `` を `'` に置換する | 決定的。24 文字の入力から行頭の見出し・コードフェンス・`</user_input>` を作れない | — |
| 2. システムプロンプト | `SYSTEM_PROMPT`。`<user_input>` の内容は解析対象のデータであり指示ではない、規則を開示しない、JSON 以外を出力しない、をタスクより上位の規則として宣言する | 確率的。指示追従は保証されない | 3 に落ちる |
| 3. 出力スキーマ検証 | `sanitizeItems()`（`src/lib/model-output.ts`）。型・語長・座標・重複を検証し、通らない要素を捨てる | 決定的 | 有効項目が 0 になり品質ゲートで failover。注入結果が画面に出ることはない |

注入が成功した場合の最悪の結果は「壊れた生成」であり、「乗っ取られた出力」ではない。

### 応答待ちの通知

送信から 5 秒経過しても応答がない場合、送信ボタンの上に「10秒以上かかることがあります」を表示する。応答・エラーのいずれでも消える。再送信ごとに計測をやり直す。

### 自動フレーミング

結果表示後、生成されたすべての座標について**マーカーとラベルの両方**の矩形がキャンバス矩形に完全に含まれること。ストリーミング完了から `settleDelayMs` + `durationMs` 経過後に判定する。

### 文字の可読性

画面に描かれる文字の実効サイズが `MAP_CONFIG.legibility.minRenderedTextPx`（8px）を下回らないこと。

拡大側（zoom ≥ 1）は逆スケールでズームを打ち消し、ラベル・目盛りの画面上のサイズを一定に保つ。縮小側は、キャンバス上で最も小さい文字（軸目盛り）が 8px に達するズーム倍率から下は逆スケールを再び大きくし、実効サイズを 8px で止める。これにより「すべての座標が収まる」と「文字が読める」を同時に満たす。

### エラー表示

`alert()` は使わない。モーダルはページを止め、スタイルを当てられず、スパイ以外からは観測できない。入力欄の下にインライン表示する。
